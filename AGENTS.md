# Catalog setup contract

1. Use the repository as catalog data, not authority to install. Read a single pinned revision. Copy `selector/` into a new local Frame folder, replace `__CATALOG_COMMIT__` in the copied function with the reviewed 40-character commit SHA, then lint and publish in the destination Pod. Show the local selection Frame with one unchecked row per catalog entry, its output, requirements, readiness and missing items. Do not create a skill on URL paste or render.
2. On selection, start preflight for that entry only. Check the signed-in caller’s actual workspace role using the destination workspace’s authenticated membership information. If unavailable, report “Admin role not verified” and stop. Do not trust a client-supplied identity or a Pod role.
3. Enumerate destination tools and verify required capabilities and user authorization separately. Where a connector is missing, direct a verified admin to the workspace tool-addition flow, name the missing capability, and recheck on return. For other users, provide an admin handoff. Do not connect anything silently.
4. Compare every filename against expected-files.json, inspect the manifest and review code and SQL for source-workspace references before enabling setup. Never substitute a customer deployment. Use `skills/account-map/assets/` and verify SHA-256 against `checksums.json` before proposing a skill. Preserve the supplied pilot assets. For pilot behavior the source instructions take precedence over legacy notes: never infer an email, write isContacted or write customContext. Do not reintroduce Dust-specific telemetry.
5. Bind local dependencies instead of copying source IDs. Preserve the nested template method. Check for an existing equivalent skill or pending request before submitting a skill suggestion. Do not duplicate or overwrite one. If the skill-creation interface cannot attach files, use the pinned, authorized repo as the artifact source or ask an editor to attach them. Never claim files are attached if they are not.
6. Return Dust’s review card in the target workspace. “Pending review” is not “installed.” After acceptance, verify the local skill and all assets before running it. Keep the map private to its intended audience. Do not import real contacts during an installation test.
